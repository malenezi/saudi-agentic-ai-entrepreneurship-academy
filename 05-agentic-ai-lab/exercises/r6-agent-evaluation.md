# R6: Agent evaluation and reliability testing

**Tool:** [Riyada](https://github.com/malenezi/riyada) · `agent-operations` (eval rubric) with the Academy's [evaluation template](../evaluation/eval-template.md) · **Course 2**, Modules 2.5 and 2.8 · **Time:** 3 hours

<div dir="rtl">

## الغرض

إجابة واحدة جيدة لا تثبت شيئاً. في هذا التمرين تقيس وكيلك على مجموعة حالات، وتكرر التشغيل لترى هل يثبت على النتيجة، ثم تغيّر شيئاً واحداً وتقيس الفرق.

## علاقته بما سبق

في [R3](r3-role-card-and-approval-matrix.md) كتبت الأخطاء الجسيمة وقاعدة الإصدار. [قالب التقييم](../evaluation/eval-template.md) يعطيك شكل مجموعة الاختبار وتركيبتها العربية. هذا التمرين هو التشغيل نفسه: دورتان كاملتان بأرقام.

## ما تحتاجه

- وكيل يعمل، ولو نموذجاً أولياً، أو أحد [قوالب الوكلاء](../agent-templates/README.md) مبنياً في أداتك.
- بطاقة الدور ومصفوفة الاعتماد من R3.

## الخطوات

1. **اكتب قاعدة الإصدار قبل أي تشغيل**، بتاريخها، في [سلّم التقييم](https://github.com/malenezi/riyada/blob/main/templates/agents/eval-rubric.ar.md): نسبة النجاح المطلوبة، الأخطاء الجسيمة صفر، وسقف التكلفة للمهمة.
2. **ابنِ 30 حالة على الأقل** بتركيبة قالب التقييم: فصحى، لهجة سعودية، مزيج، حالات حدّية، وأمان وصلاحيات. لكل حالة: السلوك المتوقع، ومعيار نجاح يُجاب عنه بنعم أو لا، وما يجب ألا يحدث.
3. **شغّل كل حالة ثلاث مرات.** الحالة تنجح إن نجحت في الثلاث. التي تنجح مرة وتفشل مرة سمِّها «متذبذبة» وسجّلها وحدها: هي ما سيراه عميلك.
4. **سجّل لكل تشغيل** في سجل التشغيل: النجاح الكلي، اللهجة، الأمان، التكلفة للمهمة، والزمن. التكلفة من [حاسبة الأكاديمية](../../04-entrepreneur-toolkit/06-unit-economics.md).
5. **صنّف كل إخفاق** في سجل الإخفاقات: فهم، معرفة، أداة، أو صلاحية. ثم السبب: تعليمات غامضة، سياق ناقص، خطأ أداة، أو حدود النموذج.
6. **غيّر شيئاً واحداً**، وهو ما يعالج أكثر الأسباب تكراراً. تغييران معاً لا تعرف بعدهما أيهما نفع.
7. **أعد تشغيل المجموعة كلها** واملأ:

| | قبل | بعد |
|---|---|---|
| النجاح (3 من 3) | /30 | /30 |
| حالات متذبذبة | | |
| الأمان والصلاحيات | /5 | /5 |
| أخطاء جسيمة | | |
| التكلفة للمهمة | | |
| ما الذي تغيّر | | |

8. **طبّق القاعدة.** إن لم تتحقق فلا إصدار، ولو تحسنت النسبة.

## تحدٍّ إضافي: تكافؤ العربية والإنجليزية

اختر عشر حالات واكتب كلاً منها مرتين: بالعربية وبالإنجليزية، بالمعنى نفسه والمعيار نفسه. **نسبة التكافؤ** = عدد الأزواج التي جاءت نتيجتها واحدة في اللغتين ÷ عدد الأزواج. سجّل معها أين كان الفشل: زوج نجح بالإنجليزية وفشل بالعربية يعني أن عميلك العربي يحصل على منتج أضعف. حدّد المستهدف أنت قبل التشغيل؛ مع عشرة أزواج، الزوج الواحد عشر نقاط.

## اقرأ الفرق بحذر

في 30 حالة، الحالة الواحدة تساوي 3.3 نقطة مئوية. الانتقال من 24 إلى 25 ليس تحسناً تبني عليه. إن احتجت إلى تمييز فروق صغيرة فزد الحالات، وابدأ بالفئة التي يكثر فيها الإخفاق.

## المساران

- **قليل البرمجة:** الحالات في جدول، والتشغيل باليد أو بعقدة تكرار، والحكم لك.
- **المسار العميق:** برنامج يشغّل المجموعة عند كل تغيير ويحفظ النتائج. الحكم على اللغة والنبرة يبقى لإنسان.

## معيار الإنجاز

- [ ] قاعدة الإصدار مؤرخة قبل أول تشغيل.
- [ ] 30 حالة على الأقل، وفيها 10 باللهجة السعودية و5 للأمان والصلاحيات.
- [ ] كل حالة شُغّلت ثلاث مرات، والمتذبذبة مسجّلة.
- [ ] حالات الأمان والصلاحيات 100%، مهما كانت النسبة الكلية.
- [ ] جدول قبل وبعد لتغيير واحد، وكل إخفاق مصنَّف.
- [ ] النموذج وإصداره وتاريخ التشغيل مكتوبة مع كل نتيجة.
- [ ] مجموعة الاختبار مرّت من فحص [R8](r8-data-governance.md) قبل إرسالها إلى أي أداة.

**English.** Run two full evaluation cycles on your own agent. Write the release rule first, build at least 30 cases with the Academy's Arabic composition, run every case three times and count a case as passed only when it passes all three, classify each failure, change one thing, and re-run the whole set. With 30 cases, one case is worth 3.3 percentage points, so small differences are not evidence of improvement. Safety and authority cases must be 100% whatever the overall rate.
